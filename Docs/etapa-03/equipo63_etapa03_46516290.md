## 2. Decisiones en las que participé
Participé en la decisión de cómo organizar el repositorio separando la teoría (en la carpeta de la etapa) de los scripts puros (en la carpeta de sql) para que quede más limpio. También estuve de acuerdo en proponer que cada regla de integridad de nuestra base de datos lleve un nombre manual, buscando facilitar el testeo posterior.

## 3. Problemas o dificultades identificadas
Noté que si dejábamos todos los archivos sueltos (tanto los textos como los scripts), la entrega de esta etapa iba a quedar muy desordenada. Por otro lado, analizando cómo íbamos a probar la base, vi que si dejábamos que SQL asigne los nombres automáticos de las restricciones, se nos iba a complicar bastante redactar el informe de validación cuando tuviéramos que atajar los errores.

## 4. Soluciones o propuestas realizadas
Para organizar mejor el trabajo del grupo, armé la carpeta `etapa-03` exclusiva para nuestros archivos `.md` y moví la parte de código a la carpeta `sql`. En cuanto a la base de datos, le sugerí a mi compañero que estaba armando el script (`minimarket24_bd.sql`) que defina los nombres de los constraints a mano, así nos ahorrábamos problemas al documentar las pruebas.
